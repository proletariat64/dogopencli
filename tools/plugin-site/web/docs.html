DEVELOPER GUIDE

开始之前插件结构接口与 SDK校验与验收发布插件给 Agent 的文档

FROM ONE QUERY TO A CAPABILITY

构建你的第一个插件。

插件是独立安装的业务查询能力。宿主管理认证、传输、结果与缓存，插件保留原生业务语义。

01 / 先确认你要解决的问题

先在插件广场检查是否已有相同能力。新业务 leaf 需确认当前接口、只读操作、原生主键、分页与日期语义；历史文档不代表当前生产行为。

按开发手册确认 simple / complex 范围，获得人工确认后形成 spec / sample，再进入实现。

阅读完整开发手册 ↗

02 / 一个目录，一项能力

my-plugin/
├── leaf.json      # 领域、名称、操作与字段语义
├── adapter.py     # 请求构造和原生响应解析
└── README.md      # 使用说明与已知边界

ZIP 根目录直接包含 leaf.json，不加外层目录。不要打包认证、浏览器 profile、配置、缓存或业务数据。

从可运行样例开始：List + Get manifest · adapter.py · Get-only。

03 / 使用宿主接口

场景契约
标准列表与分页List SDK
独立原生详情Get SDK
依赖查询与编排Custom SDK
完整性、错误与发布Result policy

完整 manifest / adapter 接口 · 权威 manifest 校验器

只允许已核实的查询操作。插件不选择退出码，不私自打印诊断，不绕过宿主认证和传输限制。

04 / 校验、打包，再验收

在 dogopencli 仓库中运行：

rtk proxy uv run python tools/leaf-dev/leaf.py verify /path/to/plugin
rtk proxy uv run python tools/leaf-dev/leaf.py pack /path/to/plugin --output /tmp/new-delivery

输出目录必须不存在。产物包括 ZIP、SHA256SUMS 与 delivery.json。静态校验不导入 adapter，也不等于运行时或生产业务验收。对同一 ZIP 分别完成隔离安装、fake-response 测试和已授权的只读业务 UAT。

05 / 分享你的插件

回到插件广场，选择“发布插件”，上传 ZIP，填写新版本与发布密钥。版本是站点发布标签，不是 leaf.json 字段；不要在 manifest 增加未支持字段。

发布后可立即浏览、下载和复制安装命令。相同插件 + 版本不可覆盖；更新需发布新版本。历史版本保留在详情的版本选择中。

dogopencli plugins install <完整 ZIP 下载地址>
dogopencli plugins list --format text

仅安装可信发布者的插件：安装会加载 Python adapter。本站标识仅证明静态结构校验通过，不证明发布者身份或生产验收。

发布密钥仅用于请求，不存入浏览器。HTTP 入口仅在可信公司网络或受保护隧道使用发布功能；可用时配置 HTTPS。

06 / Agent 可以从这里开始

纯文本入口、完整开发指南和 JSON 目录，可直接交给编码 Agent。

llms.txt · Agent 开发指南 · JSON 插件目录

GET /plugins/api/catalog
PUT /plugins/api/releases/<version>
Authorization: Bearer <publisher token>
Content-Type: application/zip
Content-Length: <ZIP bytes>

<raw ZIP bytes>

上传最大 50 MiB，解压最大 100 MiB，最多 1000 项。201 发布成功；400 包无效；401 密钥无效；409 版本已存在；413 超限；503 发布未启用。
