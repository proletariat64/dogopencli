# 按选定查询能力建模

Status: accepted
Date: 2026-09-08

用户选择方案 B：运行时仅建模选定的查询能力，以插件扩展；每项对外能力对应明确的 CLI 命令及参数。完整菜单与后端地图继续保留在研究资料中，不要求先实现所有菜单、写入及管理功能的运行时模型。

## 取舍

方案 A 先建立完整后端地图，再由配置选择端点，适合平台目录或通用 SDK；本项目是单机单人的纯查询 CLI，维护未使用能力会增加验证和变更成本。采用 B 后，每次扩展都需要补齐所选查询的请求、参数、响应及错误契约。

插件只能提供经过核实的查询行为，HTTP 方法或页面名称本身不能证明只读。菜单可见、请求曾成功和完整契约已验证分别记录，权限不足不能当作空结果。

本决策确定建模范围和插件化方向。`payment` 命令分组、插件打包粒度及具体参数仍在设计中，不能由本 ADR 推断为已实现或已接受的完整命令规格。

依据：[通用研究](../research/general/2026-09-08-platform-access.md)与[付款研究](../research/payment/2026-09-08-payment-operations.md)。
