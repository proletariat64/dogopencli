# Temporary query cache and external duckdog selectors

Accepted for [#157](https://github.com/proletariat64/dogopencli/issues/157). Each enabled list-like leaf, including `fx trade`, owns one temporary SQLite slot containing its last published nonempty acquisition. Explicit refresh atomically replaces that slot; valid empty refresh, hard failure and strict incomplete rejection preserve it. Default list replays the saved variant and applies only explicit declared local filters. Live and genuine native detail actions are inquiry-only and never cache results; list refresh never crawls details. Leaf prune deletes only its slot and is idempotent without creating an absent database.

Historical datasets, imports, merging and retention belong to external **duckdog**. Online cash `--entity ANY` reads native `instId` values once from the configured read-only `liquidity/reference/entities` selector. The frozen finite universe and acquisition quality remain visible; offline replay never opens duckdog. Ordinary queries require no DuckDB installation or database. Configured private repository-local data is permitted and excluded from Git; this implementation creates no external data artifacts.

All list output defaults to JSON with limit 100 and offset zero. Limit zero displays all remaining matched rows without changing native acquisition budgets. The `--all` flag, cached get, detail refresh and liquidity ledger balances leaf are removed. Cash online defaults to `ALIPAYGM`; FX online without ID or dates defaults to the previous complete GMT+08 day. Neither default filters no-argument offline replay. Daily native `balance` means closing book balance by confirmed business convention; unavailable closing available balance stays unavailable.

This decision supersedes the cache partitioning, coupled list/detail persistence and historical retention portions of ADRs 0003, 0016, 0017 and 0018, and related persistence promises in ADRs 0008–0014. Inquiry-only authorization, native identity/contracts and ADR 0019 usable-incomplete quality policy remain. Empty-refresh preservation is a new publication exception. Legacy business cache rows and capture/detail metadata are invalidated once before new publication, without migration or backup; configuration, credentials, profiles, source inputs and duckdog are preserved. Historical evidence remains historical and does not prove production acceptance of this change.
