## 结论

本轮本地知识库调查尚不能定义 `collection va-value` 的业务对象。2026-09-26 操作者指出，`va-value` 是此前调查收款菜单时由 agent 提出的后续候选名，而非操作者提供的产品术语或菜单名。因此不能把命名缺口转交给操作者，也不能将它自动解释为 VA 规则、费用、池、号码或实体账户。此记录仅提供历史语义和页面核验结果，不提供生产查询契约，也不是可实施规格。

先在 `/home/ubuntu/dev/dogpdkb/graphify_flatten_ready/` 执行 `graphify query`，再读取对应源 Markdown；未重建图谱或保存结果到知识库。查询包含 `VA value VA值 VA号码 VA账户` 及 `VA库 VA号码库 PTR VA Library`。图查询有预算截断，因此不以图返回缺失作不存在证明。随后针对全目录 Markdown 执行大小写不敏感字面搜索 `va[-_ ]?value|VA值|VA价值`，无匹配；这只说明这些拼写未出现在该本地快照中，不证明当前生产没有相关能力。

## 现有生产证据与导航线索

[收款总览](2026-09-23-collection-discovery.md) 记录了实际菜单 **PTR Collection VA Library**，相对路径 `productPTRManagement/VaLibrary`，但当时只验证菜单。历史 PTR 文档能解释该名称的用途，不能证明它就是agent 提出的 VA value，也不能证明其现行请求、参数、权限或覆盖范围。该页面只能作为后续只读导航线索；不得调用开户、分配、启停或发起 PTR 等动作。

[VA 规则研究](2026-09-23-collection-va-rule-query.md) 的 907 条规则及三个详情样本属于规则对象。[VA 池研究](2026-09-23-collection-va-pool-query.md) 未建立独立池列表或物理/实体 VA 账户查询契约。[收款总览](2026-09-23-collection-discovery.md) 的 VA 费用查询当时成功为空，没有非空 schema。这三类证据均不能重命名为 va-value。

### 初始专用浏览器核验（两页）

2026-09-26，专用 Chrome 的 CDP `127.0.0.1:9222` 可用，版本元数据表明当前为 headless。仅列出已有 page target 并读取页面 DOM，不新建 target、不点击控件、不发送业务请求，也不读取或保存 Cookie、token、生产行、账号值或完整页面文本。已有两个 target 分别为 **VA Capacity Monitoring** 与 ifundboss 银行账户 VA 规则详情；前者外层路径为 `collectionProductManagement/networkConstruction/VACapacityMonitoring`，iframe 指向先前已记录的 `voucher/VACapacityMonitoring`。两页当前可读取的菜单/页面文本中，未匹配到 `value`、`VA value`、`VA值` 或 `VA价值` 标签。

这是这两个已打开页面的有限观察，不是完整生产菜单遍历。结合 [收款总览](2026-09-23-collection-discovery.md) 已观察的 22 个收款菜单，本轮仍没有与 `va-value` 明确对应的入口；尤其不能把容量监控或 PTR Collection VA Library 按名称重新解释为该能力。仓库文档和 Git 历史也未记录该候选名对应的既有产品入口。未观察到 `va-value` 的原生查询，因此无可验证的 endpoint、参数或响应契约。应撤回把它当成现成能力的推断；只有从新菜单或页面证据明确识别业务对象后，才能另立查询设计。

## 设计前置条件

1. 不把 agent 提出的候选名当成需求事实。若以后从实际菜单或页面标签识别出明确的新业务对象，先记录其使用问题及与上述对象的关系。
2. 观察该对象的原生查询，确认 endpoint、method、action、输入编码、默认范围、稳定标识、字段、分页和业务成功条件。历史模型不进入 allowlist。
3. 对拟公开的每个 CLI 参数逐项提供生产查询证据和 UAT，包括匹配、枚举、多值、空值、分页与缓存语义；尚未证明的参数不暴露。
4. 保存脱敏生产证据后建立 GitHub 规格/工单，再在新分支实现。本记录不注册命令、不新增允许端点，也不把术语未决的能力标为 ready。
