# Export and import

Export retrieves native inquiry data online. Import writes an exact saved export
to its registered local Duckdog asset offline. Report these outcomes separately.

## Drive the authorized journey

1. Inspect installed leaves and public `workflow --help`. Read
   `docs/agents/export-import-workflow.md` for the common contract; for history
   read `docs/agents/bounded-history.md`, and for repair read
   `docs/agents/repair-workflow.md`. Use the selected configuration throughout.
2. Translate user intent into native arguments, explicit full/history mode and
   requested write action. Reuse existing authorization. Resolve missing business
   scope with the user; keep actual capability limits visible. Let the public
   planner validate and freeze dates, parameters, binding and work packages.
   Inspect the saved plan before execution. For a declared Get or qualified
   List/detail composition, use the public operation/identity/detail options and
   preserve their selected root/components; do not enroll Get-only leaves as
   datasets or discover new relationships during export.
3. Run the saved export plan. Preserve exact export identities and acquisition
   conclusions. Preview limits/projection affect presentation only. After partial
   failure, inspect retained outcomes and continue authorized unresolved work;
   independently completed exports remain usable.
4. For gaps, compile a repair plan from the saved baseline, inspect its frozen
   selection, then execute it. Programs select gaps and native windows. Retain
   original exports unchanged. Diagnose access/source failures before expanding
   a native run.
5. Compile an import plan from exact exports or a completed repair selection and
   the explicit action. Inspect scope, destination, counts and expected current
   publication. Preserve retains observations; current reconciliation/replacement
   requires the corresponding native contract and explicit action. Select exact
   export IDs rather than latest cache/export.
6. Apply the exact import plan offline. Compare public observation/current
   readback against its frozen input: values, numeric representation,
   multiplicity, count and scope. After interruption, replay the saved plan;
   committed database receipts determine whether work was already applied.
7. Report scope, export/import IDs, native date/time meaning, acquisition interval,
   counts, completeness/gaps, cache facts and committed outcome. Distinguish
   latest attempt, last complete export and current publication. Exclude
   credentials and raw business records from shared evidence.

Planning, help, inspection and status stay offline and advance no executor.
Continue consecutive explicit stages within existing authorization, without new
confirmation between stages. Stop dependent work at a failed gate while
completing independent authorized work.
